# ADR-015 — OpenAI as the application LLM provider

**Status: accepted** 2026-11-09 — selected by the project owner during stack review · type: `integration-architecture`

## Context
Role nodes need structured output, caching, and usage reporting. The owner selected OpenAI. This is an external service that receives prompts, which [ADR-008](ADR-008.md) does not cover.

## Decision
Call the OpenAI Python SDK directly inside nodes. Use three configurable tiers (economical, capable, escalation) with model IDs from environment variables, never hard-coded. Use Structured Outputs with Pydantic models and re-validate replies. Send only synthetic and public content until a data-governance decision says otherwise.

## Alternatives
| Option | Tradeoff |
| --- | --- |
| Anthropic Claude | Strong fit with existing Claude Code tooling; not the owner's choice. |
| Provider-agnostic layer | Easier switching, but adds a dependency and can hide provider features. |

## Consequences
Single-provider dependency kept behind a thin client. Prompts leave the machine under OpenAI API terms. Claude Code remains the authoring tool only.

## Validation
Pin dated model snapshots per tier; record model, prompt version, and token usage per run; EV-01–EV-13 pass.

## Revisit
Before any private data, on material price or quality change, or if Structured Outputs no longer fit the contracts.
