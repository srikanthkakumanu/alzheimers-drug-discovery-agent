# ADR-013 — Pydantic v2 models and strict typing

**Status: accepted** 2026-11-09 — selected by the project owner during stack review · type: `data-architecture`

## Context
Records, handoffs, LLM output, tool results, and settings cross boundaries where silent shape errors would corrupt decisions.

## Decision
Define one Pydantic v2 model per contract ([data contracts](../docs/architecture/data-contracts.md)); encode invariants as validators; load settings with pydantic-settings (`SecretStr` for keys). Annotate all code and gate merges on `mypy --strict`.

## Alternatives
| Option | Tradeoff |
| --- | --- |
| Dataclasses + manual checks | Lighter, but validation logic scatters and drifts. |
| pyright instead of mypy | Faster and strict, but the team standard is mypy; either is acceptable. |

## Consequences
Malformed data fails early with typed errors; validator rules can later be shared by the CLI and graph. Slightly more boilerplate.

## Validation
Model validators reproduce every repository validator rule on the existing corpus; `mypy --strict` passes in CI.

## Revisit
If validation cost becomes material or a schema registry is introduced.
