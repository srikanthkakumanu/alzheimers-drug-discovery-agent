# ADR-010 — Offline document validation and bounded Claude hook feedback

**Status: proposed** — awaiting owner review · type: `development-tooling`

## Context
Local Python validators, tests, and a Claude Stop hook were added earlier. The user now requests design documentation only; no application implementation or tooling changes are authorized in this pass.

## Decision
Retain existing helpers unchanged and document their actual coverage. Use them to check current documents where applicable, while leaving future evaluation and validation improvements as proposals. Treat Stop feedback as advisory because its continuation guard can skip a repeated check.

## Alternatives
| Option | Tradeoff |
| --- | --- |
| Claim structural checks establish scientific truth | Misrepresents what the tests can observe. |
| Expand implementation during documentation review | May improve tooling but violates the requested phase boundary. |

## Consequences
Documentation can be reviewed without new code. Existing fixed record counts, exact native entry-point assumptions, and ID/filename coupling limit extensions; later implementation must address those deliberately.

## Validation
Run existing checks and report actual results. A manual semantic audit covers ADR quality, stale claims, and documentation-stage consistency that the current code does not enforce.

## Revisit
Revisit the validator contract, descriptive filename support, and behavior evaluations only after the documentation review authorizes implementation work.

**Update 2026-11-09:** at the owner's request the validator was rewritten to be schema-based (minimum counts from `config/settings.json`, new rating-evidence, score-history, ADR, `.env` deny-rule, and runtime-ignore checks) and the hook gained clearer failure reporting. Still structural only.
