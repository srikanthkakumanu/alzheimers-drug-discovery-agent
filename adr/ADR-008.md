# ADR-008 — Disabled integration inventory and local secret boundaries

**Status: proposed** — awaiting owner review · type: `integration-architecture`

## Context
The MCP file lists capability names without real server implementations. Empty environment placeholders exist, and the current local validators do not need external services.

## Decision
Keep integrations disabled until their implementation, capabilities, access policy, and failure behavior are reviewed. Keep credentials local and outside prompts, evidence, and handoffs. Native Claude configuration remains separate from the descriptive integration inventory.

## Alternatives
| Option | Tradeoff |
| --- | --- |
| Enable assumed MCP servers | Appears integrated but relies on unverified names and unspecified access. |
| Build all connectors first | Adds maintenance and external dependencies before the required research flow is validated. |

## Consequences
The design can be reviewed offline and avoids invented connectivity. Actual retrieval, authentication, rate limits, caching, and qualified lab-data access remain future work.

## Validation
Existing checks verify the disabled inventory and blank template. A local hook is an executable validation helper, not a research-data connector or a network boundary.

## Revisit
Revisit one connector at a time after selecting a real implementation and evaluating its tool contract.

**Scope note 2026-11-09:** this ADR covers research-data connectors (literature, vector store, lab data, web search). The application LLM provider and tracing service are external services governed by [ADR-015](ADR-015.md) and [ADR-018](ADR-018.md).
