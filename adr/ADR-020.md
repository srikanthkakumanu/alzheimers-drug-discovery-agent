# ADR-020 — GitHub Actions quality gates

**Status: accepted** 2026-11-09 — selected by the project owner during stack review · type: `development-tooling`

## Context
Quality checks must run on every change without spending API budget.

## Decision
On push and pull request: repository validator and its tests; after application code exists, also ruff, `mypy --strict`, and offline pytest. Live-model evaluation runs only on manual dispatch with repository secrets and a budget cap ([testing strategy](../docs/delivery/testing-strategy.md)).

## Alternatives
| Option | Tradeoff |
| --- | --- |
| Live evaluation on every push | Catches regressions early, but costs money and leaks nothing useful on doc changes. |
| No CI | Free, but checks get skipped. |

## Consequences
Fast, free default CI; live quality is checked deliberately.

## Validation
Workflow passes on a clean checkout without secrets.

## Revisit
When release cadence requires scheduled live evaluation.
